# План тестирования 
**Проект:** "SmartCloth" 
---

## 1. Что тестируем 

Тестированию подлежат следующие компоненты и функции:

### 1.1 Функционал 
*   **Мобильные приложения (iOS/Android):**
    *   Регистрация/Авторизация.
    *   **Подсистема сбора погоды:** Импорт данных, уведомления о резких изменениях .
    *   **Персонализация:** Построение термомодели, сбор обратной связи "холодно/жарко".
    *   **Рекомендации:** Генерация слоев (базовый, средний, верхний) с учетом планов на день.
    *   **Цифровой гардероб:** Загрузка фото, автораспознавание, создание луков.
*   **Визуализация:**
    *   3D-рендеринг аватара по параметрам тела.
    *   Виртуальная примерка одежды.
*   **Нефункциональные требования:**
    *   Работа в Offline-режиме (кэширование рекомендаций).
    *   On-device privacy.

### 1.2 Не тестируем 
*   Платежный шлюз (используются готовые решения партнеров, проверяем только факт перехода).
*   Версии ОС ниже заявленных требований.

## 2. Окружение тестирования

Тестирование проводится на следующих конфигурациях:

### 2.1 Операционные системы (Mobile Clients)
*   **iOS:** Версия 14.0 и выше.
*   **Android:** Версия 8.0 и выше.
*   **Web (PWA):** Chrome, Safari (последние стабильные версии).

### 2.2 Оборудование (Device Lab)
*   **Минимальные требования:** Смартфоны с ОЗУ от 3 ГБ.
*   **Графика:** Поддержка OpenGL ES 3.0 / WebGL 
*   **Камера:** Проверка модуля распознавания одежды на камерах разного разрешения.
*   **Датчики:** Геолокация (GPS) для погодного сервиса.

### 2.3 Сетевое окружение
*   Стабильный Wi-Fi.
*   4G/LTE/3G.
*   **Эмуляция Offline:** Полное отсутствие сети для проверки кэша.

## 3. Типы ошибок и приоритеты

### Типы проверяемых ошибок
1.  **Логически-алгоритмические:** Рекомендация зимней куртки при +20°C (сбой термомодели).
2.  **Визуальные (3D/UI):** Артефакты на 3D-модели, нарушение пропорций тела, наезд текста.
3.  **ML/AI ошибки:** Неверное распознавание типа одежды (брюки распознаны как юбка).
4.  **Производительность:** Время отклика > 3 сек, долгая загрузка 3D-сцены.
5.  **Безопасность:** Передача персональных данных в открытом виде.

### Приоритеты (Severity)
*   **Blocker:** Падение приложения при запуске, невозможность получить прогноз.
*   **Critical:** Неверный прогноз погоды (риск здоровью), утечка данных.
*   **Major:** Ошибки в 3D-отображении, сбои в сохранении гардероба.
*   **Minor:** Грамматические ошибки, мелкие визуальные недочеты.

## 4. Методы тестирования

*   **Функциональное тестирование:** Ручная проверка сценариев использования.
*   **Интеграционное тестирование:** Проверка связки `API Погоды -> Backend -> ML Модель -> Клиент`.
*   **Нагрузочное тестирование:** Эмуляция "утреннего пика" (много запросов в 8:00 утра).
*   **Полевое тестирование:** Проверка рекомендаций в реальных погодных условиях.
*   **Тестирование безопасности:** Анализ трафика (проверка шифрования TLS 1.3).

## 5. Условия начала, остановки и завершения

### 5.1 Критерии начала (Entry Criteria)
*   Развернут Staging-сервер с подключенными погодными API.
*   Готова сборка мобильного приложения.
*   Наполнен тестовый каталог одежды.

### 5.2 Условия приостановки (Suspension Criteria)
*   Недоступность внешнего API погоды более 4 часов (блокер для работы алгоритмов).
*   Падение 3D-движка на всех устройствах.

### 5.3 Критерии завершения (Exit Criteria)
*   Успешное прохождение 100% блокирующих и критических тест-кейсов.
*   Время отклика системы не превышает 3 сек.
*   Точность рекомендаций подтверждена на тестовой группе (> 80%).
*   Отсутствие багов приоритета High и выше.
